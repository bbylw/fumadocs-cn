**Markdown/MDX：** Markdown 是一种用来撰写格式化文字的标记语言。Fumadocs 原生支援 Markdown 与 MDX (Markdown 的超集) 。

**[Bun](https://bun.sh)：** 一种 JavaScript 执行阶段环境，本指南会使用它来执行指令码。如果您偏好使用 Node.js，可以改用 [unrun](https://gugustinette.github.io/unrun/guide/getting-started.html#cli)。

若要进一步自订，具备一些 React.js 的基础知识会很有帮助。

## 自动安装 [#automatic-installation]

需要 Node.js 22 或以上版本。

```npm
npm create fumadocs-app
```

系统会询问您要使用哪个内建范本：

* **框架**：Next.js、React Router、TanStack Start、Waku 和 Astro。
* **内容来源**：Fumadocs MDX 或 Astro 内容集合。

接著会初始化一个新的 Fumadocs 应用程式，并预设设定好以下功能：

* [LLM 整合](/docs/integrations/llms)。
* [动态中继资料图片](/docs/integrations/og)。

<Callout title="要从现有的程式码库开始？">
  您可以参考[手动安装](/docs/manual-installation)指南开始使用。
</Callout>

### 尽情享用吧！ [#enjoy]

请在 docs 资料夹中建立您的第一个 MDX 档案。

```mdx title="content/docs/index.mdx"
---
title: Hello World
---

## Yo what's up
```

以开发模式执行应用程式：

```npm
npm run dev
```
以下整理了一些您可能会遇到的常见问题。

<Accordions>
  <Accordion id="upgrade-fumadocs" title="遇到 API 缺失或程式错误吗？">
    该 API 或修正可能只在较新的版本中提供。请[升级 Fumadocs](/docs/upgrade) 后再试一次。
  </Accordion>

  <Accordion id="change-base-url" title="如何变更文件的基底路由？">
    路由由 Astro 负责处理。请先搬移 docs 路由 (`/docs/*` -&gt; `/info/*`) 。

    

    
      ```ts title="app/routes.ts"
      import { route, type RouteConfig } from '@react-router/dev/routes';

      export default [
        route('info/*', 'routes/docs.tsx'), // [!code highlight]
        // ...
      ] satisfies RouteConfig;
      ```
    

    

    

    最后，在 `source.ts` 中更新页面的基础 URL：

    ```ts title="lib/source.ts"
    import { loader } from 'fumadocs-core/source';

    export const source = loader({
      baseUrl: '/info', // 改为新值 [!code highlight]
    });
    ```

    范本在 `lib/shared.ts` 中将此值定义为 `docsRoute`，请在该处修改，Markdown 连结才会跟著更新。
  </Accordion>

  <Accordion id="multi-docs" title="如何实作多组文件？">
    建议使用[版面配置页签](/docs/ui/layouts/docs#layout-tabs)。
  </Accordion>

  

      
  

  
    <Accordion id="vite-context-error" title="使用 React context 时发生错误？">
      Vite 的预先打包 (pre-bundling) 有一些奇怪的问题：[#3910](https://github.com/vitejs/vite/issues/3910)。
      请务必将 Fumadocs 排除在预先打包之外，并将其加入 `noExternal`：

      ```ts title="vite.config.ts"
      import { defineConfig } from 'vite';

      export default defineConfig({
        resolve: {
          // 视需要加入其他 Fumadocs 相依套件
          noExternal: ['fumadocs-core', 'fumadocs-ui', 'fumadocs-openapi', '@fumadocs/base-ui'],
        },
      });
      ```
    </Accordion>
  

  
    <Accordion id="node-issues" title="已知的 Node.js 问题">
      如果您遇到类似以下的 Turbopack 错误：

      ```
      JSON file not found: FileSystemPath { ... path: "lib/locales/sources/file.json.json" }
      ```

      这通常是因为不支援 `require(esm)` ([#3312](https://github.com/fuma-nama/fumadocs/issues/3312)) ，请升级至 Node.js 22+。

      在 Node.js 23.1 上，如果您在建置正式版本时遇到以下错误：

      ```
      Could not find a production build in the '.next' directory.
      ```

      这是已知问题，详见 [#1021](https://github.com/fuma-nama/fumadocs/issues/1021)，您可以将 Node.js 升级至 23.6.0+ 版本。
    </Accordion>

    <Accordion id="dynamic-route" title="使用动态路由会影响效能吗？">
      设定 `generateStaticParams` 后，Next.js 会将动态路由转换为静态路由，
      因此速度与静态页面一样快。

      您可以[启用静态汇出](/docs/deploying/static)，以取得静态的建置输出。
    </Accordion>
  
</Accordions>
