title: 比较
description: Fumadocs 与其他现有框架有何不同？
---

Fumadocs 深受 Nextra 启发，例如路由惯例 (Routing Conventions) 。这也是为什么
Fumadocs 同样有 `meta.json`。

Nextra 比 Fumadocs 更具主观设计 (opinionated) ，也因此在 Fumadocs 中，您需要手动设定更多项目，
而不是单纯编辑一个设定档就好。

如果您希望对各方面拥有更多掌控权，例如将其整合进既有的程式码库，或实作进阶路由，
Fumadocs 会是很好的选择。

### 功能比较表 [#feature-table]

| 功能         | Fumadocs | Nextra             |
| ---------- | -------- | ------------------ |
| 静态生成       | 是        | 是                  |
| 快取         | 是        | 是                  |
| 浅色／深色模式    | 是        | 是                  |
| 语法突显       | 是        | 是                  |
| 目录         | 是        | 是                  |
| 全文搜寻       | 是        | 是                  |
| i18n       | 是        | 是                  |
| Git 最后编辑时间 | 是        | 是                  |
| 页面图示       | 是        | 是，透过 `_meta.js` 档案 |
| RSC        | 是        | 是                  |
| 远端来源       | 是        | 是                  |
| SEO        | 透过中继资料   | 是                  |
| 内建元件       | 是        | 是                  |
| RTL 版面配置   | 是        | 是                  |

### 其他功能 [#additional-features]

透过 [TypeDoc](https://typedoc.org) 等第三方函式库支援的功能，不会列于此处。

| 功能                  | Fumadocs | Nextra |
| ------------------- | -------- | ------ |
| OpenAPI 整合          | 是        | 否      |
| TypeScript 文件产生     | 是        | 否      |
| TypeScript Twoslash | 是        | 是      |

## Mintlify [#mintlify]

Mintlify 是一项文件服务。与 Fumadocs 相比，它虽然提供免费方案，但并非完全免费，也不是开源软体。

Fumadocs 的功能不如 Mintlify 强大，例如 Mintlify 的 OpenAPI 整合就是一例。
身为 Fumadocs 的作者，如果您对目前建构文件的方式感到满意，我并不建议您从 Mintlify 改用 Fumadocs。
不过，我相信对所有想打造精美文件的 React.js 开发者而言，Fumadocs 都是合适的工具。

## Docusaurus [#docusaurus]

Docusaurus 是一个以 React.js 为基础的强大框架，透过外挂与自订主题，提供许多
很棒的功能。

### 复杂度较低 [#lower-complexity]

由于 Fumadocs 是为了与 React 框架整合而设计，您可能需要对 React.js 有较多了解才能上手。
相对地，Fumadocs 的可自订性也更高。

若只是建置简单的文件网站，而且不需要任何框架专属的功能，Docusaurus 可能是更好的选择。

### 外挂 [#plugins]

透过外挂，您可以轻松实现许多功能；Docusaurus 的生态系确实更为庞大，且有众多贡献者共同维护。

相较之下，Fumadocs 的弹性让您能够自行实作这些功能，但可能需要花更多时间调整，才能达到您满意的效果。
