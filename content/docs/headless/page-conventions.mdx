---

> 本指南仅适用于使用 `loader()` API 的内容来源，例如 **Fumadocs MDX**。

## 概览 [#overview]

Fumadocs 会通过 [`loader()`](/docs/headless/source-api) 从你的内容目录生成**页面 slug** 与**页面树** (侧边栏项目) ，
路由功能则交由你的 React 框架处理。

你可以用类似文件系统路由的方式定义文件夹与页面。

<Files>
  <Folder name="content/docs（内容目录）" defaultOpen>
    <File name="index.mdx" />

    <File name="getting-started.mdx" />
  </Folder>
</Files>

若要进一步自定义输出结果，可以使用[加载器插件](/docs/headless/source-api/plugins)。

## 文件 [#file]

若是 [MDX](https://mdxjs.com) &amp; Markdown 文件，你可以通过 frontmatter 自定义页面信息。

```mdx
---
title: My Page
description: Best document ever
icon: House
---

## Learn More
```

Fumadocs 会读取以下属性来构建页面树。

| 名称            | 说明                   |
| ------------- | -------------------- |
| `title`       | 页面标题                 |
| `description` | 页面说明                 |
| `icon`        | 图标名称，请参阅[图标](#icons) |

<Callout title="小提示">
  页面信息由内容来源 (例如 **Fumadocs MDX**) 提供。

  在 Fumadocs MDX 中，你可以通过 [`schema`](/docs/mdx/collections#schema-1) 选项自定义 frontmatter schema。
</Callout>

### Slugs [#slugs]

页面的 slugs 是根据其文件路径生成的。

| 路径 (相对于内容文件夹)     | slugs             |
| ----------------- | ----------------- |
| `./dir/page.mdx`  | `['dir', 'page']` |
| `./dir/index.mdx` | `['dir']`         |

## 文件夹 [#folder]

文件夹用来组织多个页面，你可以创建 [Meta 文件](#meta) 来自定义文件夹。

### 文件夹分组 [#folder-group]

根据默认，将文件放入文件夹会改变其 slugs。
若不想影响子文件的 slugs，可以用括号包住文件夹名称。

| 路径 (相对于内容文件夹)             | slugs      |
| ------------------------- | ---------- |
| `./(group-name)/page.mdx` | `['page']` |

### 根文件夹 [#root-folder]

将文件夹标记为根文件夹，仅显示目前打开的根文件夹中的项目。

```json title="meta.json"
{
  "title": "Name of Folder",
  "description": "The description of root folder (optional)",
  "root": true
}
```

例如，当你打开根文件夹 `framework` 时，其他文件夹 (例如 `headless`) 就不会显示在侧边栏和其他导航元素中。

<Files>
  <Folder name="framework" defaultOpen>
    <File name="index.mdx" />

    <File name="current-page.mdx" className="text-fd-primary! bg-fd-primary/10!" />

    <File name="other-pages.mdx" />
  </Folder>

  <Folder name="headless (hidden)" className="opacity-50" disabled defaultOpen>
    <File name="my-page.mdx" />
  </Folder>
</Files>

<Callout title="Fumadocs UI">
  Fumadocs UI 会将根文件夹渲染为[布局选项卡](/docs/ui/layouts/docs#layout-tabs)，让用户能在各个根文件夹之间切换。
</Callout>

### 根类型 [#root-type]

`root` 也可以接受字符串，用来指定根文件夹的**类型**：
在同一个上层范围内，相同类型的根文件夹可以互相切换，例如同一篇文档的不同版本。

<Files>
  <Folder name="v1" defaultOpen>
    <File name="meta.json" />

    <File name="index.mdx" />

    <File name="guide.mdx" className="text-fd-primary! bg-fd-primary/10!" />
  </Folder>

  <Folder name="v2" defaultOpen>
    <File name="meta.json" />

    <File name="index.mdx" />

    <File name="guide.mdx" className="text-fd-primary! bg-fd-primary/10!" />
  </Folder>
</Files>

```json tab="v1/meta.json"
{
  "title": "1.0.0",
  "root": "version"
}
```

```json tab="v2/meta.json"
{
  "title": "2.0.0",
  "root": "version"
}
```

`root: true` 其实就是默认类型，会以选项卡形式显示。

切换到同类型的另一个根文件夹时，页面会对应到其**结构投影**，也就是相对于根文件夹位于相同路径的页面：

| 页面                    | 在 `v2` 中的投影                     |
| --------------------- | ------------------------------- |
| `v1/guide.mdx`        | `v2/guide.mdx`                  |
| `v1/python/guide.mdx` | `v2/python/guide.mdx`，嵌套根文件夹会保留 |

<Callout title="Fumadocs UI">
  Fumadocs UI 会为当前页面路径上的每个根文件夹渲染一个[下拉菜单](/docs/ui/layouts/docs#tabs-groups)，用来在同类型的根文件夹之间切换。完整示例请参阅[版本管理](/docs/navigation#versioning)。
</Callout>

## Meta [#meta]

在文件夹中创建 `meta.json` 文件，即可自定义该文件夹。

```json tab="meta.json"
{
  "title": "Display Name",
  "icon": "MyIcon",
  "pages": ["index", "getting-started"],
  "defaultOpen": true
}
```

```ts tab="meta.ts"
export default {
  title: 'Display Name',
  icon: 'MyIcon',
  pages: ['index', 'getting-started'],
  defaultOpen: true,
};
```

若你的内容来源支持，也可以用代码撰写 meta 文件 (`meta.ts` 或 `meta.js`) ，并将数据设为默认导出 (default export) 。

| 名称            | 说明                      |
| ------------- | ----------------------- |
| `title`       | 显示名称                    |
| `icon`        | 图标名称，请参阅[图标](#icons)    |
| `defaultOpen` | 默认展开文件夹                 |
| `collapsible` | 文件夹内容是否可收合 (默认：`true`)  |
| `pages`       | 文件夹项目 (详见下文)            |
| `pagesIndex`  | 索引项目 (详见下文)             |

### 页面 [#pages]

文件夹中的项目默认依字母顺序排序，你可以使用 `pages` 添加项目或调整项目顺序。

```json title="meta.json"
{
  "pages": ["index", "getting-started"]
}
```

> 指定此字段后，只有列在 `pages` 中的项目才会被纳入。

| 类型         | 语法                                                                 | 说明                                               |
| ---------- | ------------------------------------------------------------------ | ------------------------------------------------ |
| **路径**     | `./path/to/page`                                                   | 指向页面或文件夹的路径。                                     |
| **分隔项目**   | `---Label---`<br />`---[Icon]Label---`                             | 两个节之间的分隔符 (支持图标) 。                              |
| **链接**     | `[Text](url)`<br />`[Icon][Text](url)`<br />`external:[Text](url)` | 插入链接 (支持图标) <br />加上 `external:` 前缀即可将链接标记为外部链接。 |
| **其余项目**   | `...`                                                              | 纳入其余页面 (依字母顺序排序) 。                               |
| **反向其余项目** | `z...a`                                                            | 反向排序的**其余项目**。                                   |
| **展开**     | `...folder`                                                        | 展开文件夹中的项目。                                       |
| **排除**     | `!item`                                                            | 从 `...` 或 `z...a` 中排除某个项目。                       |

```json title="meta.json"
{
  "pages": [
    "components",
    "---My Separator---",
    "...folder",
    "...",
    "!file",
    "!otherFolder",
    "[Vercel](https://vercel.com)",
    "[Triangle][Vercel](https://vercel.com)"
  ]
}
```

<Callout type="warn" title="不可有重复的 URL">
  同一个页面 URL 在整个页面树中只能出现一次。
  基于相同原因，页面项目也不得重复。

  这是刻意的设计，让 Fumadocs 能够仅依据当前的 pathname 找出作用中的树状项目。
</Callout>

### 文件夹索引 [#folder-index]

当文件夹拥有索引项目时，该文件夹即可点击，点击后会跳转至索引项目。

默认情况下，索引项目是各文件夹中的 `index` 文件。你也可以自行指定文件夹的索引项目，支持 **路径** 与 **链接** 两种类型。

```json tab="meta.json (Path)"
{
  // 假设该文档夹下有 "overview.mdx" 文档
  "pagesIndex": "overview"
}
```

```json tab="meta.json (Link)"
{
  "pagesIndex": "[Example](https://example.com)"
}
```

## 图标 [#icons]

由于 Fumadocs 并未内置图标函数库，你必须在运行时将图标名称转换为 JSX 元素，再以组件的形式渲染。

你可以为 `loader()` 加入 [`icon` 处理器](/docs/headless/source-api#icons)。

## i18n 路由 [#i18n-routing]

你可以为 i18n 路由定义不同的风格。

```ts title="lib/i18n.ts"
import type { I18nConfig } from 'fumadocs-core/i18n';

export const i18n: I18nConfig = {
  // 默认值
  parser: 'dot',
  // 或
  parser: 'dir',
};
```

<Tabs items={['dot', 'dir']}>
  <Tab>
    在文件名后加上 `.{locale}`，即可为不同语言添加 Markdown/meta 文件，例如：

    <Files>
      <Folder name="content/docs" defaultOpen>
        <File name="meta.json" />

        <File name="meta.cn.json" />

        <File name="get-started.mdx" />

        <File name="get-started.cn.mdx" />
      </Folder>
    </Files>

    默认语系的文件可省略语系代码。
  </Tab>

  <Tab>
    所有内容文件皆依语言分别放在各自的文件夹中：

    <Files>
      <Folder name="content/docs" defaultOpen>
        <Folder name="en" defaultOpen>
          <File name="meta.json" />

          <File name="get-started.mdx" />
        </Folder>

        <Folder name="cn" defaultOpen>
          <File name="meta.json" />

          <File name="get-started.mdx" />
        </Folder>
      </Folder>
    </Files>
  </Tab>
</Tabs>

## 路径参数 [#path-params]

系统会依参数的每个值，各生成一个名为 `[name]` 的文件夹。请在该文件夹的 meta 文件中，于 `staticParams` 列出这些值：

<Files>
  <Folder name="content/docs" defaultOpen>
    <Folder name="[framework]" defaultOpen>
      <File name="meta.json" />

      <File name="deploy.mdx" />
    </Folder>
  </Folder>
</Files>

```json title="[framework]/meta.json"
{
  "title": "Framework",
  "staticParams": [{ "framework": "waku" }, { "framework": "astro" }]
}
```

| 路径 (相对于内容文件夹)              | slugs                                       |
| -------------------------- | ------------------------------------------- |
| `./[framework]/deploy.mdx` | `['waku', 'deploy']`, `['astro', 'deploy']` |

meta 文件会应用到每个生成的文件夹。页面会以 [props](/docs/markdown#props) 的形式接收其参数，也可以通过 `loader()` 返回的 `page.params` 取得。

在 `meta.ts` 中，你也可以改为导出一个以参数为输入的函数，并将 `staticParams` 作为具名导出：

```ts title="[framework]/meta.ts"
const names = { waku: 'Waku', astro: 'Astro' };

export const staticParams = [{ framework: 'waku' }, { framework: 'astro' }];

export default ({ framework }: { framework: keyof typeof names }) => ({
  title: names[framework],
});
```

<Callout title="小提示">
  若没有任何地方列出 `[name]` 文件夹的值，它就会维持为一般文件夹。
</Callout>

### 页面参数 [#page-params]

页面也可以在 frontmatter 中列出 `staticParams`。若所属文件夹也有列出，则只会针对两者共有的值生成该页面。

```mdx title="[framework]/fumadocs-mdx.mdx"
---
title: Fumadocs MDX
staticParams:
  - framework: waku
---
```

### 静态路径 [#static-paths]

位于固定路径的文件，优先级高于动态生成的文件。例如，`astro/deploy.mdx` 会取代 `[framework]/deploy.mdx` 所生成的 `astro` 页面。meta 文件也适用相同规则。

### 在地化页面 [#localized-pages]

激活 [i18n](#i18n-routing) 时，语系本身的文件会优先于其备用语系的文件。以 `/cn/docs/astro/deploy` 为例，会依序采用第一个存在的文件：

1. `astro/deploy.cn.mdx`
2. `[framework]/deploy.cn.mdx`
3. `astro/deploy.mdx`
4. `[framework]/deploy.mdx`

在地化页面会优先从 `meta.cn.json` 读取 `staticParams`。使用 `dir` 解析器时，每个语言文件夹会各自列出其值。
