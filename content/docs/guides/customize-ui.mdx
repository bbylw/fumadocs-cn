Fumadocs UI 提供预先建置的元件以简化开发，定位介于「将所有 UI 程式码安装到您的程式码库」与「具有强烈既定设计取向的套件」之间。

虽然 Fumadocs UI 本身在弹性与向下相容性方面有许多设计考量，但若使用方式不当，这些机制可能无法发挥作用。

> 若您的 AI 代理可能会修改您的 UI，也建议将本指南提供给它们参考。

### Props [step] [#props]

您可以先确认元件提供的选项是否已能满足您的需求，例如：

```tsx
<DocsLayout sidebar={{ enabled: false }}>{/* 内容 */}</DocsLayout>
```

或是透过 props 设定容器的样式：

```tsx
<DocsLayout
  containerProps={{
    className: '...',
  }}
>
  {/* 内容 */}
</DocsLayout>
```

各元件的详细说明请参阅 [Fumadocs UI](/docs/ui) 章节。

大多数选项都支援传入 JSX 元素，让您使用自订元件。
这种做法应能满足大多数使用情境，例如在目录下方或侧边栏中新增区块。

### CSS [step] [#css]

当样式需求较为复杂时，Fumadocs UI 的部分元件会附加专属的 `id` &amp; `data-` 属性，方便您选取。
您可以在 CSS 选择器中以它们为目标：

```css
#nd-docs-layout #nd-subnav {
  background-color: purple;
}

[data-toc-popover] {
  background-color: purple;
}
```

**请避免使用侵入性的样式，或任何预设了特定 DOM 结构的写法**，因为这类写法难以保证向后相容，尤其是在推出新的 UI 功能时。

```css title="Bad Example"
/* 请避免像这样选取元素！ */
[data-toc-popover] > div {
  background-color: purple;
}
```

使用 CSS 的做法有一定风险，因为只有 `id` &amp; `data-` 属性能依照各自的生命周期进行版本控管，因此请尽可能优先采用其他做法。

### 透过 CLI 安装 [step] [#install-via-cli]

如果您的需求超出现有选项所能提供的范围，或是自订的 CSS 样式变得过度侵入，Fumadocs CLI 会是很强大的工具。

您可以在相关元件的文件中看到类似的提示，表示该元件可透过 CLI 安装，例如：

至于**版面配置元件** (通常由多个元件组成) ，Fumadocs CLI 提供专用的 `customize` 指令，让您进行更细致的选择。

```npm
npx @fumadocs/cli@latest customize
```

除了安装整个版面配置元件，您也可以选择只安装某个 **slot** (版面配置元件中可替换的部分) 。
执行上方的指令即可查看所有选项。

安装完成后，请务必改用已安装的型别，而非从 Fumadocs UI 汇出的型别。例如，若您已安装 `layout/docs`，请更新您的汇入：

```tsx
// [!code --]
import type { DocsLayoutProps } from 'fumadocs-ui/layouts/docs';
// [!code ++]
import type { DocsLayoutProps } from '@/components/layout/docs';
```

这能确保您的本机元件与 Fumadocs UI 解耦。

虽然 Fumadocs CLI 让您能完全掌控 UI 程式码，但仍有几点值得注意：

* 已安装的元件将无法再收到 UI 更新。
* 您可以使用 Fumadocs CLI 重新安装元件，但先前的自订内容将会被清除。 (您可以选择要覆写哪些档案) 
* Fumadocs CLI 会预设您使用最新版本的 Fumadocs Core 与 UI。
