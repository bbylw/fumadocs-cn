除了 `@fumadocs/asyncapi/ui` 之外，其余皆为无头式。

| 路径                              | 模组                        |
| ------------------------------- | ------------------------- |
| `@fumadocs/asyncapi`            | 页面：文件、其伺服器，以及您的元件         |
| `@fumadocs/asyncapi/operation`  | 单一 operation：其频道、参数、讯息与回复 |
| `@fumadocs/asyncapi/playground` | operation 频道上的工作阶段        |

## 页面 [#page]

`createAsyncAPIRenderer()` 会接收您的元件，并回传 ``，该元件接受所产生页面的 props。

```tsx title="components/api-page.tsx"
'use client';
import { type CodeBlockProps, createAsyncAPIRenderer } from '@fumadocs/asyncapi';
import { Operation } from '@/components/my-operation';
import { SchemaUI } from '@/components/my-schema';

export const AsyncAPIPage = createAsyncAPIRenderer({
  components: {
    Operation,
    SchemaUI,
    CodeBlock({ lang, code }: CodeBlockProps) {
      return (
        <pre>
          <code className={`language-${lang}`}>{code}</code>
        </pre>
      );
    },
  },
});
```

| 元件          | 算绘内容                                         |
| ----------- | -------------------------------------------- |
| `Operation` | 页面中的每个 operation，请参阅 [Operation](#operation) |
| `SchemaUI`  | 参数、标头及讯息酬载的 JSON schema                      |
| `Layout`    | 选用，用来包覆已渲染的 operation                        |

### Hooks [#hooks]

页面底下的元件可以读取页面的状态。

| Hook                 | 回传值                   |
| -------------------- | --------------------- |
| `useAsyncAPI()`      | 已解参照的文件 (`doc`) 与页面选项 |
| `useComponents()`    | 传入页面的元件               |
| `useServer()`        | 伺服器列表、目前选取的伺服器及其变数    |
| `useRenderContext()` | 页面的算绘选项，例如 `content`  |

若要自行算绘 operation，请改为挂载 ``，以取代 `createAsyncAPIRenderer()`。

## Operation [#operation]

`` 只会推导一次 operation 的详细资讯：套用 traits，并解析其频道、参数、讯息与回复。

```tsx title="components/my-operation.tsx"
'use client';
import {
  OperationProvider,
  type PageOperationProps,
  useOperation,
  useOperationSecurity,
} from '@fumadocs/asyncapi/operation';

export function Operation(props: PageOperationProps) {
  return (
    <OperationProvider {...props}>
      <Content />
    </OperationProvider>
  );
}

function Content() {
  const { title, channel, parameters, messages } = useOperation();
  const security = useOperationSecurity();

  return (
    <>
      <h2>{title}</h2>
      <code>{channel.address}</code>
      <ul>
        {parameters.map((param) => (
          <li key={param.name}>{param.name}</li>
        ))}
      </ul>
      {messages.map((message) => (
        <section key={message.id}>
          <h3>{message.name}</h3>
          {message.examples.map((example) => (
            <pre key={example.id}>{JSON.stringify(example.payload, null, 2)}</pre>
          ))}
        </section>
      ))}
      <p>{security.operation.map((item) => item.id).join(', ')}</p>
    </>
  );
}
```

| Hook                     | 回传值                                |
| ------------------------ | ---------------------------------- |
| `useOperation()`         | 已解析详细资讯的 operation                 |
| `useOperationSecurity()` | 所选伺服器与该 operation 的安全性方案 (两者皆会套用)  |
| `useChannelMessages()`   | 读者在该频道上接收与传送的讯息，涵盖该频道的所有 operation |

## 互动测试区 [#playground]

`usePlayground()` 会在 `` 之下，透过传输层连线至 operation 的频道。

```tsx
'use client';
import { usePlayground } from '@fumadocs/asyncapi/playground';
import { mqttTransport } from '@/lib/mqtt-transport';

export function Playground() {
  const { url, status, connect, disconnect, send, log } = usePlayground({
    // 叠加在页面的 `playground.transports` 之上
    transports: { mqtt: mqttTransport },
  });
  if (!url) return null; // 此伺服器没有可用的传输层

  return (
    <>
      <button onClick={status === 'closed' ? connect : disconnect}>{status}</button>
      {send && <button onClick={() => send('{"type":"ping"}')}>Ping</button>}
      {log.map((entry) => (
        <p key={entry.id}>
          {entry.type} {entry.message?.name} {entry.data}
        </p>
      ))}
    </>
  );
}
```

* 位址参数、query 与验证输入都属于表单 `stf`，`url` 会随其值更新。
* 连线期间即可使用 `send`，除非该连线仅能接收讯息。
* 收到的讯息会与频道上各讯息的酬载进行比对，`entry.message` 即为对应的文件化讯息；二进位讯息则存放于 `entry.binary`。

### 传输层 [#transports]

传输层负责连线至某个协定的伺服器，范例请参考 [MQTT 范例](/docs/integrations/asyncapi/api-page#custom-transports)。系统会依序从 `usePlayground()` 的 `transports`、页面的 `playground.transports` 中选取，最后才使用内建的 WebSocket 传输层。

`usePlaygroundTransport()` 接受相同的 `transports`，并回传所选伺服器对应的传输层；若没有任何传输层能连线至该伺服器，则回传 `undefined`。
