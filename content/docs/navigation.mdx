## 版本管理 [#versioning]

若读者需要查阅旧版发行版本的文件，可以同时保留多个版本。您可以选择让各版本共用同一个网站，或分别部署：

| 方式                         | 适用情境                    |
| -------------------------- | ----------------------- |
| [根类型](#root-type)          | 仅部分文件需要版本管理，且各版本位于同一个网站 |
| [完整版本管理](#full-versioning) | 对整个网站进行版本管理，每个版本各自部署    |

### 根类型 [#root-type]

为每个版本各建立一个资料夹，并在 `meta.json` 中将它们标记为同一类型的根资料夹：

<Files>
  <Folder name="content/docs" defaultOpen>
    <Folder name="v1" defaultOpen>
      <File name="meta.json" />

      <File name="index.mdx" />

      <File name="getting-started.mdx" />

      <File name="legacy-api.mdx" />
    </Folder>

    <Folder name="v2" defaultOpen>
      <File name="meta.json" />

      <File name="index.mdx" />

      <File name="getting-started.mdx" />
    </Folder>
  </Folder>
</Files>

```json tab="v1/meta.json"
{
  "title": "1.0.0",
  "root": "version"
}
```

```json tab="v2/meta.json"
{
  "title": "2.0.0",
  "root": "version"
}
```

侧边栏只会显示目前开启版本的内容，而文件版面配置会算绘一个下拉选单，让您在各版本之间切换，选项以各版本的 `title` 作为标签。
切换时会停留在相同位置：系统会导向另一个版本中的同一页面；若该版本中没有此页面，则导向其索引页：

| 页面                         | 切换至 2.0.0                  |
| -------------------------- | -------------------------- |
| `/docs/v1/getting-started` | `/docs/v2/getting-started` |
| `/docs/v1/legacy-api`      | `/docs/v2`，即索引页            |

<Callout title="小提示">
  类型名称 (`"version"`) 可以任意命名，仅用于识别类型：位于同一父层下、类型相同的根资料夹
  可以互相切换。
</Callout>

### 完整版本管理 [#full-versioning]

有时您会想为整个网站进行版本管理，例如 https://v14.fumadocs.dev (Fumadocs v14) 与 https://fumadocs.dev (最新版 Fumadocs) 。

您可以为某个版本的文件建立一个 Git 分支 (例如命名为 `v2`) ，并将其部署为独立的应用程式，放在另一个子网域上，例如 `v2.my-site.com`。

您也可以选择在文件中加入其他版本的连结。
相较于部分版本管理，这种做法有以下优点：

* 易于维护：当您迭代开发或升级相依套件时，旧版文件／分支不会受到影响。
* 一致性更佳：不只文件本身，您的首页 (以及其他页面) 也会一并纳入版本管理。
