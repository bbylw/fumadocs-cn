Fumadocs 为标记语言 MDX 提供了许多实用的扩充功能。以下简要介绍 Fumadocs 预设的 MDX 语法。

> MDX 并非 Fumadocs 唯一支援的格式。事实上，您可以使用任何算绘器，例如无头式 CMS。
>
> 详情请参阅[自订内容来源](/docs/integrations/content/custom)。

## MDX [#mdx]

我们建议使用 MDX，它是 Markdown 的超集，支援 JSX 语法。
您可以汇入元件并在文件中使用，甚至能直接撰写 JavaScript。

请参阅：

* [MDX 语法](https://mdxjs.com/docs/what-is-mdx/#mdx-syntax)。
* 同时也支援 GFM (GitHub Flavored Markdown) ，请参阅 [GFM 规格](https://github.github.com/gfm)。

```mdx noCopy
import { Component } from './component';

<Component name="Hello" />

## Heading

### Heading

#### Heading

Hello World, **Bold**, _Italic_, ~~Hidden~~

1. First
2. Second
3. Third

- Item 1
- Item 2

> Quote here

![alt](/image.png)

| Table | Description |
| ----- | ----------- |
| Hello | World       |
```
Fumadocs 预设支援 YAML 格式的 frontmatter，其中 `title` 在 Fumadocs UI 中代表页面标题 (`h1`) 。

```mdx
---
title: This is a document
---

...
```

因此，撰写 Markdown/MDX 时通常不会使用 h1 标题 (`# Heading`) ，除非您有自订的页面标题算绘逻辑。

若您的内容来源支援，也可以在程式码中汇出 frontmatter。汇出的值会合并并覆盖 YAML frontmatter，且可以读取 [props](#props)：

```mdx
---
title: Deploy
---

 export const frontmatter = {
  description: `Deploy your ${props.framework} site.`,
};
```

<Callout title="在 Fumadocs MDX 中">
  您可以使用 [`schema`](/docs/mdx/collections#schema-1) 选项新增 frontmatter 属性。详情请参阅[自订 frontmatter](/docs/mdx#customize-frontmatter)。
</Callout>

### 自动连结 [#auto-links]

内部连结会使用您 React 框架的 `` 元件，以支援预先载入并避免整页重新载入。

基于安全考量，外部连结会自动加上预设的 `rel="noreferrer noopener" target="_blank"` 属性。

```mdx
[My Link](https://github.github.com/gfm)

This also works: https://github.github.com/gfm.
```
适合用来加入连结。

```mdx
import { HomeIcon } from 'lucide-react';

<Cards>
  <Card href="/docs" title="Documentation">
    Browse the full documentation.
  </Card>
  <Card title="href is optional">Cards can hold plain content too.</Card>
  <Card icon={<HomeIcon />} href="/" title="Home">
    You can include icons too.
  </Card>
</Cards>
```

<Cards>
  <Card href="/docs" title="文件">
    浏览完整文件。
  </Card>

  <Card title="href 为选用">卡片也可以只放纯内容。</Card>

  <Card href="/" title="首页">
    您也可以加上图示。
  </Card>
</Cards>

#### 「延伸阅读」区块 [#further-reading-section]

您可以参考以下写法：

```tsx title="page.tsx"
import { getPageTreePeers } from 'fumadocs-core/page-tree';
import { source } from '@/lib/source';

<Cards>
  {getPageTreePeers(source.getPageTree(), '/docs/my-page').map((peer) => (
    <Card key={peer.url} title={peer.name} href={peer.url}>
      {peer.description}
    </Card>
  ))}
</Cards>;
```

这会以卡片形式列出同一资料夹中的其他页面。

### Callouts [#callouts]

适合用来加入提示或警告，预设即已内建。您可以指定 Callout 的类型：

* `info` (预设) 
* `warn`/`warning`
* `error`
* `success`
* `idea`

```mdx
<Callout>Hello World</Callout>

<Callout title="Title" type="warn">
  Hello World
</Callout>

<Callout title="Title" type="error">
  Hello World
</Callout>

<Callout title="Title" type="idea">
  Hello World
</Callout>
```

<Callout>你好，世界</Callout>

<Callout title="标题" type="warn">
  你好，世界
</Callout>

<Callout title="标题" type="error">
  你好，世界
</Callout>

<Callout title="标题" type="idea">
  你好，世界
</Callout>

### 标题 [#headings]

每个标题都会自动加上锚点，并将空格等无效字元转换为有效格式 (例如 `Hello World` 会转为 `hello-world`) 。

```md
# Hello `World`
```
目录 (TOC) 会根据标题自动产生，您也可以自订标题在目录中的呈现方式：

```md
# Heading [!toc]

This heading will be hidden from TOC.

# Another Heading [toc]

This heading will **only** be visible in TOC, you can use it to add additional TOC items.
Like headings rendered in a React component:

<MyComp />
```
您可以加上 `[#slug]` 来自订标题锚点。

```md
# heading [#my-heading-id]
```

您也可以搭配目录设定一起使用，例如：

```md
# heading [toc] [#my-heading-id]
```

若要让他人透过连结直接前往特定标题，请将标题 ID 加到杂凑片段 (hash fragment) 中：`/page#my-heading-id`。

    },
  },
});

  satteriOptions: {
    remarkCodeTabOptions: {
      parseMdx: true, // [!code ++]
    },
  },
});

### Props [#props]

页面的 props 可在 MDX 中透过 `props` 存取。例如，位于 `[framework]` 资料夹中的页面，会从其[路径参数](/docs/page-conventions#path-params)取得 `framework`：

```mdx title="[framework]/deploy.mdx"
## Deploy on {props.framework}

Deploy your {props.framework} site.
```

表达式在目录、搜寻索引以及提供给 LLM 的 Markdown 中，同样会被替换为其计算后的值。在 Astro 页面上，上方标题的 ID 会是 `deploy-on-astro`。

您也可以将[自订 props](/docs/headless/source-api#custom-props) 传递给页面。

### Show [#show]

依条件算绘内容。Fumadocs MDX 预设已透过 [Remark Show](/docs/headless/mdx/remark-show) 启用此功能。

`when` 是可读取 [props](#props) 的 JavaScript 表达式：

```mdx title="[framework]/deploy.mdx"
<show when={props.framework === 'astro'}>

## Adapters

Add an adapter to your Astro config.

</show>
```

此区段只会在 `framework` 为 `astro` 的页面上算绘。在其他页面上，这个区段也不会出现在目录、搜寻索引，以及提供给 LLM 的 Markdown 中。

您也可以用 `<show>` 包住[步骤](#steps)：

```mdx title="[framework]/deploy.mdx"
### 建置 [step]

<show when={props.framework === 'astro'}>

### 新增转接器 [step]

</show>

### 部署 [step]
```

未算绘的步骤不会计入编号：在 Astro 页面上，Deploy 是第 3 步；在其他页面上则是第 2 步。

[页签群组](#tab-groups)中的程式码区块也是如此。只有在对应的程式码区块有算绘时，该页签才会显示。
