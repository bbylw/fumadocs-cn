**Fumadocs** 框架指的是 UI + Core + 内容来源的组合。与其说是框架，Fumadocs 更像是一种思维框架，其中每一层都能各自作为独立的函式库使用。

## 设计理念 [#philosophy]

Fumadocs 的诞生，是为了让建置文件的过程更具自订弹性，成为一个不预设立场、不强加既定做法的文件框架，**一个您可以打破的「框架」**。

### 更少的抽象化 [#less-abstraction]

虽然大多数框架都透过设定档进行设定，但当您想微调细节时，往往不够有弹性。
您既无法控制它们如何算绘页面，也无法掌控其内部逻辑。

Fumadocs 希望您自行撰写程式码，并与软体的其他部分协同运作。它不仰赖设定档，而是让您清楚了解应用程式的运作方式，并可完全自订。

### 无缝整合 [#seamless-integration]

Fumadocs 与您的 React 框架紧密整合，提供实用的工具与美观的 UI。

您依然可以使用框架原有的功能，例如**静态网站生成 (Static Site Generation)&#x20;**。框架的一切仍是您熟悉的样子。

### 可组合的 UI [#composable-ui]

Fumadocs UI (预设主题) 唯一提供的就是**使用者介面**。这套 UI 有其既定的设计主张，目的是提供更好的行动装置响应式设计与使用者体验。

不过，我们采用受 Shadcn UI 启发、弹性更高的做法。[Fumadocs CLI](/docs/cli) 让您能「fork」Fumadocs UI 的其中一部分，并完全自订。

### 伺服器优先的做法 [#server-first-approach]

传统上，静态网站产生器都是**静态**的。

然而，Fumadocs 采用了以 React 伺服器元件为基础的伺服器优先做法。
透过明确划分伺服器与用户端的边界，内容得以动态呈现并具备互动性。

您可以从伺服器撷取资料来显示内容，或整合 CMS 以接收即时更新。内容始终保持最新，且易于维护。

### 精简 [#minimal]

Fumadocs 由 Fuma 与众多贡献者共同维护，并注重程式码库的可维护性。

我们并不打算满足大家想要的每一项功能，而是更专注于把基本功能做到完善，并持续妥善维护。
您也可以透过贡献，让 Fumadocs 变得更加实用！

## 何时使用 Fumadocs [#when-to-use-fumadocs]

Fumadocs 在设计上注重弹性，不局限于特定的使用情境。

* `fumadocs-core` 是用于建构文件的无头式 UI 函式库。
* `fumadocs-mdx` 是处理 MDX 内容的实用函式库。

对大多数 Web 应用程式来说，单靠原生 React.js 已经不够用了。
现在我们往往还需要部落格、作品展示页、常见问题页等。在这些情况下，Fumadocs 能协助您更轻松地建构
文件，并减少样板程式码。

如果您有兴趣，可以参阅[比较](/docs/comparisons)。

### 文件 [#documentation]

Fumadocs 专注于**撰写体验**，提供美观的主题以及多种文件自动化工具。

它能协助您更快速地迭代程式码库，同时确保文件始终跟上进度。
本网站就是使用 Fumadocs 建置的文件网站范例，可供您参考。

### 部落格网站 [#blog-sites]

大多数 React.js 框架本身就足以满足部落格网站的需求。

Fumadocs 另外提供了语法突显、文件搜寻，以及预设主题 (Fumadocs UI) 等工具。
让您不必重新发明轮子。
