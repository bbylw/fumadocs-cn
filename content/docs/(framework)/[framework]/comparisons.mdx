## Nextra [#nextra]

Fumadocs 深受 Nextra 启发，例如路由惯例 (Routing Conventions) 。这也是为什么
Fumadocs 同样有 `meta.json`。

Nextra 比 Fumadocs 更具主观设计 (opinionated) ，也因此在 Fumadocs 中，你需要手动设置更多项目，
而不是单纯编辑一个配置文件就好。

如果你希望对各方面拥有更多掌控权，例如将其集成进既有的代码库，或实现高级路由，
Fumadocs 会是很好的选择。

### 功能比较表 [#feature-table]

| 功能         | Fumadocs | Nextra             |
| ---------- | -------- | ------------------ |
| 静态生成       | 是        | 是                  |
| 缓存         | 是        | 是                  |
| 浅色／深色模式    | 是        | 是                  |
| 语法高亮       | 是        | 是                  |
| 目录         | 是        | 是                  |
| 全文搜索       | 是        | 是                  |
| i18n       | 是        | 是                  |
| Git 最后编辑时间 | 是        | 是                  |
| 页面图标       | 是        | 是，通过 `_meta.js` 文件 |
| RSC        | 是        | 是                  |
| 远程来源       | 是        | 是                  |
| SEO        | 通过元数据   | 是                  |
| 内置组件       | 是        | 是                  |
| RTL 布局   | 是        | 是                  |

## Mintlify [#mintlify]

Mintlify 是一项文档服务。与 Fumadocs 相比，它虽然提供免费方案，但并非完全免费，也不是开源软件。

Fumadocs 的功能不如 Mintlify 强大，例如 Mintlify 的 OpenAPI 集成就是一例。
身为 Fumadocs 的作者，如果你对目前构建文档的方式感到满意，我并不建议你从 Mintlify 改用 Fumadocs。
不过，我相信对所有想打造精美文档的 React.js 开发者而言，Fumadocs 都是合适的工具。

## Docusaurus [#docusaurus]

Docusaurus 是一个以 React.js 为基础的强大框架，通过插件与自定义主题，提供许多
很棒的功能。

### 复杂度较低 [#lower-complexity]

由于 Fumadocs 是为了与 React 框架集成而设计，你可能需要对 React.js 有较多了解才能上手。
相对地，Fumadocs 的可自定义性也更高。

若只是构建简单的文档网站，而且不需要任何框架专属的功能，Docusaurus 可能是更好的选择。

### 插件 [#plugins]

通过插件，你可以轻松实现许多功能；Docusaurus 的生态系确实更为庞大，且有众多贡献者共同维护。

相较之下，Fumadocs 的弹性让你能够自行实现这些功能，但可能需要花更多时间调整，才能达到你满意的效果。
