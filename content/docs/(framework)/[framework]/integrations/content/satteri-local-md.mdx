## 简介 [#introduction]

`@fumadocs/satteri/local-md` 是适用于本地 Markdown/MDX 文件的内容来源，改用 [Sätteri](https://github.com/bruits/satteri) 编译，而非 unified/remark 管线。

它与 [`@fumadocs/local-md`](/docs/integrations/content/local-md) 的 API 相同，同样无需打包，因此可直接在运行时运作，不需要类型生成或打包步骤。

若你想使用 Sätteri 编译器、它的插件模型，以及 Fumadocs Sätteri 默认组合，请可选此内容来源。

### 差异 [#differences]

* 编译结果一律为 JavaScript，因此不提供虚拟 JavaScript 引擎选项，渲染时会使用原生引擎。
* 插件为 Sätteri 插件，需通过 `satteriOptions` 设置，而非 remark/rehype 插件。

<Callout type="warn">
  请勿将不受信任的 Markdown/MDX 文件放在 `dir` 中，因为这些文件可能会以 JavaScript 形式运行，或参照服务端的文件。
</Callout>

## 安装设置 [#setup]

```package-install
@fumadocs/satteri shiki
```

> 之所以需要安装 `shiki`，是因为打包工具必须将它外部化 (externalize) 。

创建 `localMd` 实例，并将它连接到 Fumadocs：

```ts title="lib/source.ts"
import { dynamicLoader } from 'fumadocs-core/source';
import { localMd } from '@fumadocs/satteri/local-md';

const docs = localMd({
  dir: 'content/docs',
});

const docsLoader = dynamicLoader(docs.dynamicSource(), {
  baseUrl: '/docs',
});

export async function getSource() {
  return docsLoader.get();
}
```

### Schema [#schema]

传入 `frontmatterSchema` 与 `metaSchema`，即可自定义验证用的 schema：

```ts title="lib/source.ts"
import { localMd } from '@fumadocs/satteri/local-md';
import { pageSchema, metaSchema } from 'fumadocs-core/source/schema';

const docs = localMd({
  dir: 'content/docs',
  frontmatterSchema: pageSchema.extend({
    // ...
  }),
  metaSchema: metaSchema.extend({
    // ...
  }),
});
```

### 编译器选项 [#compiler-options]

`satteriOptions` 会经由 Fumadocs Sätteri 默认集传入，因此插件及其选项的设置方式与 Fumadocs MDX 相同：

```ts title="lib/source.ts"
const docs = localMd({
  dir: 'content/docs',
  satteriOptions: {
    rehypeCodeOptions: {
      themes: { light: 'github-light', dark: 'github-dark' },
    },
    mdastPlugins: [myPlugin()],
  },
});
```

传入函数即可延迟创建选项。

## 使用方式 [#usage]

`getSource()` 会返回一个[内容加载器](/docs/headless/source-api)。渲染页面的方式与 [`@fumadocs/local-md`](/docs/integrations/content/local-md#usage) 相同，只是改从 `@fumadocs/satteri/local-md` 导入。

每个页面都有 `load()`，可编译该页面并返回渲染器：

```tsx
const page = source.getPage(slugs);
const { body, toc } = await (await page.data.load()).render();
```

渲染器也提供 `structuredData` 与 `exports`，可用来取得文档或其插件所导出的值。

### 引入 [#include]

[`<include>`](/docs/mdx/include) 与 `::include` 指令皆已默认启用：

```mdx title="content/docs/page.mdx"
<include>../shared/note.md</include>
```

### 热重载 [#hot-reload]

来源会在运行时读取文件，因此默认不会监看这些文件。

<show when={props.framework === 'next'}>
  在开发期间，请在运行应用的同时，运行 `@fumadocs/local-md` 的开发服务器：

  ```json title="package.json"
  {
    "scripts": {
      "dev": "local-md dev -- next dev"
    }
  }
  ```

  将来源连接至该服务器：

  ```ts title="lib/source.ts"
  import { watchWithDevServer } from '@fumadocs/satteri/local-md/dev/ws';

  if (process.env.NODE_ENV === 'development') {
    void watchWithDevServer(docs);
  }
  ```

  这会让服务器上的来源失效，但 Next.js 仍会在浏览器中保留已渲染的页面。请在根布局中渲染 `<DevClient />`，让页面也一并刷新：

  ```tsx title="app/layout.tsx"
  import { DevClient } from '@fumadocs/satteri/local-md/dev/react-client';

  export function RootLayout({ children }) {
    return (
      <RootProvider>
        {/* [!code ++] */}
        <DevClient />
        {children}
      </RootProvider>
    );
  }
  ```
</show>

<show when={props.framework !== 'next'}>
  在开发期间，Vite 插件会通过 Vite 的文件监看器让来源失效。请将插件加入设置，并连接来源：

  <show when={props.framework === 'react-router' || props.framework === 'tanstack-start'}>

引入的文件也会受到监看。若要自行串接监看器，请监看 `docs.dir` 以及传入 `docs.onDependency()` 的文件，并在文件变更时调用 `docs.invalidateFile(path)`。

### 禁用重新验证 [#disable-revalidation]

若你只需要一次性的快照，请使用 `staticSource()`，如此一来，一般的 `loader()` 即可正常运作：

```ts title="lib/source.ts"
import { loader } from 'fumadocs-core/source';

export const source = loader(await docs.staticSource(), {
  baseUrl: '/docs',
});
```
