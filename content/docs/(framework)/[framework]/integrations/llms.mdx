## 供 LLM 使用的文档 [#docs-for-llm]

以 Markdown 格式将你的文档提供给 LLM 与 AI 代理：

```package-install
npx @fumadocs/cli feature llms
```

它会为你的 docs 集合启用处理后的 Markdown、在 `lib/source.ts` 中加入 `docsLlms`，并提供下方列出的[文件](#files)。若你偏好手动设置，可参考此处列出的生成文件。

### `docsLlms` [#docsllms]

`llms()` 会将你的文档渲染为供 LLM 使用的格式。`renderPage` 会将单一页面转换为 Markdown，且依据的是处理后的文档，而非原始文件内容：

<feature title="lib/source.ts">llms/docs-llms.ts</feature>

| 方法             | 输出                          |
| -------------- | --------------------------- |
| `index(lang?)` | `llms.txt` 索引，依据页面树创建       |
| `page(page)`   | 单一页面，以 `renderPage` 渲染      |
| `full(lang?)`  | 所有页面以 `renderPage` 渲染后合并的内容 |
| `files()`      | [供 AI 代理使用的文件](#files)的路径   |
| `serve(path)`  | 指定路径文件的回应                   |

<Callout title="renderPage 为必要选项">
  只有在传入 `renderPage` 时，才能使用 `page()`、`full()`、`files()` 与 `serve()`，因为
  Fumadocs 无从得知你的内容来源如何提供 Markdown。
</Callout>

`renderPage` 会读取页面处理后的 Markdown，因此请启用 `includeProcessedMarkdown`：

<show when={props.framework !== 'astro'}>
  <feature title="source.config.ts">llms/source.config.ts</feature>

  MDX 组件会以 JSX 语法呈现。若要将其渲染为 [Markdown 形式](/docs/headless/utils/markdown#asmarkdown)，请将[你的 MDX 组件](/docs/headless/mdx/remark-llms#jsx-elements)作为页面 props 传入。
</show>

<show when={props.framework === 'astro'}>
  ```js title="astro.config.mjs"
  import { defineConfig } from 'astro/config';
  import fumadocs from '@fumadocs/astro';

  export default defineConfig({
    integrations: [
      fumadocs({
        includeProcessedMarkdown: true, // [!code ++]
      }),
    ],
  });
  ```

  除非 MDX 组件已定义其 [Markdown 形式](/docs/headless/utils/markdown#asmarkdown)，否则会以 JSX 语法呈现。
</show>

[`@fumadocs/local-md`](/docs/integrations/content/local-md) 这类运行时内容来源会随需解析。只要传入其 `getSource`，CLI 就会生成相同的文件：

```ts
export const docsLlms = llms(getSource, {
  renderPage: (page) => `# ${page.data.title} (${page.url})

${page.data.content}`,
});
```

使用 `getSource` 时，`index()` 与 `indexNode()` 会返回 Promise，而非字符串。

### 文件 [#files]

CLI 会为 AI 代理提供以下文件：

* `/llms.txt`：文档的索引，附有每个页面 Markdown 版本的链接。
* `/llms-full.txt`：所有页面的内容。
* `<page>.md`：单一页面的 Markdown，例如 `/docs/ui.md`。位于 `/` 的页面则对应 `/index.md`。
* `<section>/llms-full.txt`：某个[节](#sections)的内容，例如 `/docs/ui/llms-full.txt`。

若要将特定页面 (例如草稿) 排除在这些文件之外，请传入 `filter`。`llms.txt` 仍会列出这些页面，但会链接至其 HTML 页面：

```ts title="lib/source.ts"
export const docsLlms = llms(source, {
  filter: (page) => page.slugs[0] !== 'drafts',
  renderPage: async (page) => `# ${page.data.title}\n\n${await page.data.getText('processed')}`,
});
```

在这些文件中，`renderUrl` 会接收链接所指向文件的路径，例如页面的 `.md` 文件。

读取页面 HTML 的 AI 代理，会通过 `<head>` 中的链接找到该页面的 Markdown：

```html
<link rel="alternate" type="text/markdown" href="/docs/ui.md" />
```

### 节 [#sections]

节是页面树中拥有独立 `llms-full.txt` 的文件夹，让 AI 代理能分段阅读大型文档。默认情况下，每个根文件夹都是一个节。在 `llms.txt` 中，文件夹对应的那一行会链接到其所属节的 `llms-full.txt`。

若要自定义节，请传入 `section`。它会接收一个文件夹，并返回该文件夹是否为节：

```ts title="lib/source.ts"
export const docsLlms = llms(source, {
  // 所有含 index 页面的文档夹
  section: (folder) => folder.index !== undefined,
  renderPage: async (page) => `# ${page.data.title}\n\n${await page.data.getText('processed')}`,
});
```

在大型网站上，你可以收合节，让 `llms.txt` 保持精简。收合的节在 `llms.txt` 中只会列为一个链接，指向该节专属的 `<section>/llms.txt`，再由该文件列出节内的页面：

```ts title="lib/source.ts"
export const docsLlms = llms(source, {
  section: (folder) => (folder.root ? { collapse: true } : false),
  renderPage: async (page) => `# ${page.data.title}\n\n${await page.data.getText('processed')}`,
});
```

节的文件会以其文件夹 index 页面的 URL 提供。若文件夹没有 index 页面，则改用其中页面所在的 URL 目录。当两个文件夹共用同一个 URL 时 (例如文件夹分组) ，请传入 `asPath`，将其中一个改放在其他路径下提供，例如 `{ asPath: '/docs/guides' }`。

<show when={props.framework === 'react-router'}>
  在 SPA 模式下，请在 `react-router.config.ts` 中预先渲染这些文件。React Router 加载配置文件时不会应用你的 Vite 插件，因此请使用 Vite 的 `runnerImport` 加载来源：

  ```ts title="react-router.config.ts"
  import type { Config } from '@react-router/dev/config';
  import { fumadocsMdx } from 'fumadocs-mdx/vite';
  import { runnerImport } from 'vite';

  export default {
    ssr: false,
    async prerender({ getStaticPaths }) {
      const paths = getStaticPaths();
      const { docsLlms } = (
        await runnerImport<typeof import('./app/lib/source')>('./app/lib/source.ts', {
          plugins: [fumadocsMdx()],
          resolve: { tsconfigPaths: true },
        })
      ).module;

      for (const path of await docsLlms.files())
        paths.push(path === '/llms.txt' || path === '/llms-full.txt' ? path : `/llms.mdx${path}`);
      return paths;
    },
  } satisfies Config;
  ```
</show>

<show when={props.framework === 'tanstack-start'}>

#### `Accept` [#accept]

<show when={props.framework !== 'astro'}>
  AI 代理可以通过 `Accept` 标头要求取得 Markdown。
</show>

<show when={props.framework === 'next'}>
  当请求偏好 Markdown 时，改为提供该页面的 Markdown：

  ```ts title="proxy.ts"
  import { NextRequest, NextResponse } from 'next/server';
  import { isMarkdownPreferred, rewritePath } from 'fumadocs-core/negotiation';

  const { rewrite: rewriteDocs } = rewritePath('/docs{/*path}', '/llms.mdx/docs{/*path}.md');

  export default function proxy(request: NextRequest) {
    const { pathname } = request.nextUrl;
    // `/docs/ui.md` 这类文档由 Next.js 设置中的 rewrites 负责提供
    const result =
      isMarkdownPreferred(request) && !/\.(md|txt)$/.test(pathname) && rewriteDocs(pathname);

    if (result) {
      return NextResponse.rewrite(new URL(result, request.nextUrl), {
        headers: { Vary: 'Accept' }, // [!code highlight]
      });
    }

    return NextResponse.next();
  }
  ```
</show>

<show when={props.framework === 'react-router' || props.framework === 'waku'}>
  当请求偏好 Markdown 时，上述中间件会以文档页面的 Markdown 回应。

  <Callout>
    预先渲染的页面会在中间件运行前就以静态文件形式提供，因此一律以 HTML 回应。
  </Callout>
</show>

<show when={props.framework === 'tanstack-start'}>
  当请求偏好 Markdown 时，重定向到该页面的 Markdown：

  ```ts title="src/start.ts"
  import { createMiddleware, createStart } from '@tanstack/react-start';
  import { redirect } from '@tanstack/react-router';
  import { isMarkdownPreferred } from 'fumadocs-core/negotiation';

  const llmMiddleware = createMiddleware().server(({ next, request }) => {
    const url = new URL(request.url);

    // `/docs/ui.md` 这类路径由文档路由负责提供
    if (
      url.pathname.startsWith('/docs') &&
      !/\.(md|txt)$/.test(url.pathname) &&
      isMarkdownPreferred(request)
    ) {
      url.pathname += '.md';
      throw redirect({ href: url.href, headers: { Vary: 'Accept' } }); // [!code highlight]
    }

    return next();
  });

  export const startInstance = createStart(() => ({
    requestMiddleware: [llmMiddleware],
  }));
  ```
</show>

<show when={props.framework !== 'astro'}>
  同一个 URL 现在有两种表示形式，因此回应需要加上 `Vary: Accept`，以避免缓存冲突。
</show>

<show when={props.framework === 'next'}>
  <Callout>
    Next.js 会舍弃 App Router 页面回应中的 `Vary`，因此文档页面的 HTML 回应无法带有此标头。若你的文档经由共用缓存提供，请在 CDN 上设置此标头。
  </Callout>
</show>

<show when={props.framework === 'astro'}>
  文档页面无法依据 `Accept` 标头提供 Markdown。Astro 中间件只会在请求时才渲染的页面上运行，而文档页面是预先渲染的。
</show>

## MCP 服务器 [#mcp-server]

通过 [MCP](https://modelcontextprotocol.io) 服务器将你的文档开放给 AI 代理使用，并提供列出、搜索及读取页面的工具。

```package-install
npx @fumadocs/cli feature mcp
```

这会在上述 [LLM 路由](#docs-for-llm)之外，再创建一个使用 Streamable HTTP 传输层的 `/api/mcp` 路由。

这些工具来自 [`fumadocs-core/mcp`](/docs/headless/utils/mcp)。

```json
{
  "mcpServers": {
    "docs": { "url": "https://your-site.com/api/mcp" }
  }
}
```

## WebMCP [#webmcp]

<Callout type="warn" title="实验性功能">
  [WebMCP](https://webmachinelearning.github.io/webmcp/) 是一项仍处于早期阶段的 Web 标准，目前可在
  Chrome 149+ 中通过 `#enable-webmcp-testing` 标志及来源试用 (origin trial) 使用。此 API 日后仍可能
  变动。
</Callout>

上述 MCP 服务器服务的是连接至你网站的 AI 代理；WebMCP 则是在读者正在浏览的页面上，将工具提供给浏览器内置的 AI 代理使用。

```package-install
npx @fumadocs/cli feature webmcp
```

它会以 [LLM 路由](#docs-for-llm)为基础，创建一个 `WebMCP` 组件。请在 `<RootProvider />` 内渲染此组件。

* `search_docs` 会查找搜索 API 路由。你可以将 `fetchClient` 替换为[其他客户端](/docs/search)。
* `read_page` 会从 <show when={props.framework === 'react-router' || props.framework === 'waku'}>`/llms.mdx/docs/page.md`</show><show when={props.framework !== 'react-router' && props.framework !== 'waku'}>`/docs/page.md`</show> 取得页面的 Markdown 内容。

## 询问 AI [#ask-ai]

你可以使用 Fumadocs CLI 安装 AI 聊天对话框。

    > Fumadocs 不提供 AI 模型，需由你自行决定。
    >
    > 你的 AI 模型可以使用上方生成的 `llms-full.txt` 文件；若搭配第三方解决方案，也能使用更多元的信息来源。
  </Tab>

  <Tab>
    ```npm
    npx @fumadocs/cli add ai/llmgateway
    ```

    它会通过 Vercel AI SDK 自动完成 [LLMGateway](https://llmgateway.io) 的设置，并为 AI 提供 `/search` 工具。

    LLMGateway 是开放源代码的 API 闸道，可将请求代理至 300 多个语言模型，因此同一个路由处理程序只需变更模型 ID 即可切换供应商。

    ```dotenv

    LLM_GATEWAY_MODEL="openai/gpt-4o"
    ```
  </Tab>

```tsx tab="components/ai/layout.tsx"
import { AIChat, AIChatPanel, useAIChat } from './search';

export function DocsLayout(props: DocsLayoutProps) {
  return (
    <AIChat>
      <ChatLayout {...props} />
    </AIChat>
  );
}

function ChatLayout(props: DocsLayoutProps) {
  const { open, setOpen } = useAIChat();

  return (
    <Layout
      {...props}
      aiChat={{ open, onOpenChange: setOpen, panel: <AIChatPanel />, trigger: true }}
    />
  );
}
```
