## 简介 [#introduction]

Fumadocs UI 提供预先构建的组件以简化开发，定位介于「将所有 UI 代码安装到你的代码库」与「具有强烈既定设计取向的包」之间。

虽然 Fumadocs UI 本身在弹性与向下兼容性方面有许多设计考量，但若使用方式不当，这些机制可能无法发挥作用。

> 若你的 AI 代理可能会修改你的 UI，也建议将本指南提供给它们参考。

### Props [step] [#props]

你可以先确认组件提供的选项是否已能满足你的需求，例如：

```tsx
<DocsLayout sidebar={{ enabled: false }}>{/* 内容 */}</DocsLayout>
```

或是通过 props 设置容器的样式：

```tsx
<DocsLayout
  containerProps={{
    className: '...',
  }}
>
  {/* 内容 */}
</DocsLayout>
```

各组件的详细说明请参阅 [Fumadocs UI](/docs/ui) 章节。

大多数选项都支持传入 JSX 元素，让你使用自定义组件。
这种做法应能满足大多数使用情境，例如在目录下方或侧边栏中添加块。

### CSS [step] [#css]

当样式需求较为复杂时，Fumadocs UI 的部分组件会附加专属的 `id` &amp; `data-` 属性，方便你选取。
你可以在 CSS 选择器中以它们为目标：

```css
#nd-docs-layout #nd-subnav {
  background-color: purple;
}

[data-toc-popover] {
  background-color: purple;
}
```

**请避免使用侵入性的样式，或任何默认了特定 DOM 结构的写法**，因为这类写法难以保证向后兼容，尤其是在推出新的 UI 功能时。

```css title="Bad Example"
/* 请避免像这样选取元素！ */
[data-toc-popover] > div {
  background-color: purple;
}
```

使用 CSS 的做法有一定风险，因为只有 `id` &amp; `data-` 属性能依照各自的生命周期进行版本控管，因此请尽可能优先采用其他做法。

### 通过 CLI 安装 [step] [#install-via-cli]

如果你的需求超出现有选项所能提供的范围，或是自定义的 CSS 样式变得过度侵入，Fumadocs CLI 会是很强大的工具。

你可以在相关组件的文档中看到类似的提示，表示该组件可通过 CLI 安装，例如：

<Installation name="layouts/docs" />

至于**布局组件** (通常由多个组件组成) ，Fumadocs CLI 提供专用的 `customize` 指令，让你进行更细致的选择。

```npm
npx @fumadocs/cli@latest customize
```

除了安装整个布局组件，你也可以选择只安装某个 **slot** (布局组件中可替换的部分) 。
运行上方的指令即可查看所有选项。

安装完成后，请务必改用已安装的类型，而非从 Fumadocs UI 导出的类型。例如，若你已安装 `layout/docs`，请更新你的导入：

```tsx
// [!code --]
import type { DocsLayoutProps } from 'fumadocs-ui/layouts/docs';
// [!code ++]
import type { DocsLayoutProps } from '@/components/layout/docs';
```

这能确保你的本地组件与 Fumadocs UI 解耦。

虽然 Fumadocs CLI 让你能完全掌控 UI 代码，但仍有几点值得注意：

* 已安装的组件将无法再收到 UI 更新。
* 你可以使用 Fumadocs CLI 重新安装组件，但先前的自定义内容将会被清除。 (你可以选择要覆盖哪些文件) 
* Fumadocs CLI 会默认你使用最新版本的 Fumadocs Core 与 UI。
